# CSA Mix 等待中的有界负 Ready 复用

日期：2026-10-30。结论：完整 Device 未见收益，候选运行时撤回；保留 248 项独立边界保护。
保留的资源范围实现仍为 `d19885ded`：1C1V 两 lane、1C2V 三 lane，全部合法 cluster 公平竞争。

## 假设与边界

资源范围版的 L3 仍存在较长组间周转和全员无业务 kernel 的空窗。
等待 Mix 到达／释放信号时，poll 每次也检查自己的 Ready inbox 和所属目录分片；
C 检查 C、Mix 两类，V 检查 V 类。这里不是扫描所有目录分片。
参考旧 demo 的 `loser_overhead.md`、`perf_opt_record.md` 中控制外壳与有界工作的思路，
候选只复用负 Ready 观察，不减少错误、完成或执行许可的校验。

普通多 block Mix 处于所需成员等待状态时，完整判空后最多跳过三次 Ready 探测，
第四次必须重新探测；组 ACK、assigned_seq、关闭信号仍每次检查。
组信号可能就绪、已有 candidate／pending／local ready、配置不合法时取消负提示。
N=1、sync_start、纯 C/V 不采用延期。提示不是 ownership，也不是 kernel 执行许可。
一个本地字节利用既有 padding，local state 仍为 288B；没有共享 ABI 或行为开关变化。

以下条件均保持：固定物理放置、全体合法 cluster 竞争、全局准入顺序及本地投影义务、
实际资源全部 ARRIVED 后执行、全部 RELEASED 后复用 mailbox、唯一领取／完成和 epoch 检查。
没有改变业务 kernel、输入、N、七项 golden 或 2308 个执行身份。

## 完整 Device 对照

源码与三件 runtime 成套切换；每批三轮七项 golden、5 次预热、100 个正式样本。
四批按 A/B/B/A 串行执行，A 为候选，B 为恢复的资源范围基线：

| 批次 | 完整 Device 中位数（us） |
| ---- | ------------------------ |
| A1 | 1929.983 |
| B1 | 1923.655 |
| B2 | 1924.861 |
| A2 | 1927.450 |

每臂 200 个样本，合并中位数 A=1928.525us、B=1923.874us，候选多 4.651us，约 0.24%。
差值很小，但两批候选均未优于两批基线，没有保留依据；不把这解释成所有负探测复用都无效。
完整 Device 包含设备启动和退出，不使用 Host 时间或 kernel 窗口替代。
54 个链接后业务 kernel 指纹一致；正式计时与本会话的编译、回归、设备查询分开。
未观察到其他 A5 CLI 重叠；本机没有任务锁，这不是系统级独占证明。

候选窗口略短，但全员计算空窗和重复组周转没有改善，不能只挑窗口下降作为收益。
这些是两次独立插桩捕获，不是 L0 成本的精确拆分；没有逐条 GM 查询次数或带宽测量，
不把源码中省下的 query 直接归为实测的 atomic／总线收益。
全员无 kernel 不等于 Scalar 全部无工作。交接拆分的阈值命中集合不同，
摘要中的 12／14 段交接总和不能直接相减当作相同任务集合的增量；存在重叠的分段也不串行相加。

## 正确性验证与保留边界

初始 368 项用例在原实现上为 120 项策略时序 RED、248 项保护 PASS；
RED 要求前三次不重新发现 Ready，属于候选策略，不表示旧业务行为有缺陷。
候选补齐三项计数器／配置保护后，21 个 C++ 目标通过，GM Mix 目标共 1110 项。
3989 项 Python 检查在末次配置保护修正前通过；最终候选 A5/A5sim 构建和静态检查通过。
严格 L4 通过两轮七项 golden、2308 个执行身份、133 条依赖、3808 个成员义务和 40193 个事件；
独立 L3 的七项 golden、完整执行身份和依赖时序也通过。
未运行候选完整 HBG 设备回归或故障矩阵，不扩大无收益候选的验收范围。

运行时代码、原生三件套及 A5sim 构建均恢复资源范围版；撤回 120 项策略用例与三项计数器专用测试。
四项既有测试恢复“下一次 fill 即可发现新 Ready”的断言，原不提前完成／不提前复用断言保留。
留下的 248 项用例覆盖四种 mask、两个 cluster 的实际成员、ARRIVED／RELEASED 等待、
自身 inbox、目录清除与推送交错、远端 inbox、新组信号、新 Ready、等待后错误，以及 N=1／sync_start。
恢复后的 21 个 C++ 目标、248 项独立保护和 3989 项 Python 检查通过，GM Mix 目标为 987 项。

## 取舍与证据

不保留该跨 poll 延期。后续若重开，应有更直接的动态证据，证明重复空 Ready 探测是主要成本，
并能控制额外状态判断及新 Ready 发现延迟；不继续仅按源码查询次数调整间隔。
本次没有新的性能成果，也不是低于 1.5ms 的最终五批验收。
