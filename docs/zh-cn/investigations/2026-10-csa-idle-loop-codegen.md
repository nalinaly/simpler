# CSA 空轮询与无记录执行边界的机器码验证

日期：2026-10-30。保留显式无记录执行边界，撤回取消调度期退避的候选。
本轮完整 Device 合并中位数为 1921.7145us，对照为 1926.2805us，仅约 0.24% 的局部改善。
没有达到低于 1.5ms 的目标，也不把这项小收益当作解决了主要计算空窗。
1C1V 两 lane、1C2V 三 lane、全部合法 cluster 竞争及固定 C/V 放置保持不变。

## 源码与最终机器码证据

复用 `simpler_dev/tests/atomic_probe/lazy_lamda_sample/A_original/disassemble.py`，
使用同版本 CANN 的 DAV3510 PEM 解码器，逐字节核对最终 ELF 中两个无记录调度函数。
每个目标函数都通过完整长度、机器字一致性及非法助记符检查，不使用 IR 或十六进制代替反汇编。
解码器 SHA256 为 `29835d2439d6dd464d34a212ad4bbd5c29af6a38465da09a6c273401d9a96dcb`。

旧工具的全 ELF 入口在当前 runtime 的 SIMT 锚点遇到 `UNDEF` 并拒绝，失败日志保留。
本轮只使用独立验证通过的完整 Scalar 调度函数，不宣称全 ELF 覆盖，也没有放宽解码门禁。
源码注释来自 DWARF 文件／行映射及对应源码，不是 ELF 自带注释。

资源范围基线的无记录函数存在两个具体问题：

- 空轮询仍无条件读取两次 `SYS_CNT`，返回值只供已关闭的阶段记录使用。
- 每次有效 kernel 入口仍根据运行时 `timing_slot` 判断是否记录。
  AIC 机器码在这个判断之前，用三条双字 store 清零 48B 的 `SchedulerExecutorTaskTrace`。
  它们位于最终 PC `0x88968`、`0x88970`、`0x88988`，不是仅从源码构造函数推测的写入。

实际入口只有在泳道 task timing 和 sampled task timing 都关闭时才选择 `WithProfiling=false`。
有采样的 L0 仍进入 `true` 版本，因此无记录版本可以显式排除 task timing 和执行协议记录分支。
这不同于此前只在函数入口重申 `profiling=nullptr` 的无收益实验；参见
[无记录热循环实验](2026-10-csa-inline-hotloop.md)。

## 取消调度期人工退避：初筛未见收益，撤回

候选删除主循环的 8→32 次 volatile 空转及包围它的两次时钟读取，启动屏障退避不变。
没有改变 Ready、ACK、错误或退出检查，也没有限制竞争者。
原样 CSA 严格 L4 和两轮七项 golden 通过，21 个 C++ 目标、3989 项 Python 检查及两平台构建通过。

| 初筛批次 | 完整 Device 中位数（us） |
| -------- | ------------------------ |
| 取消退避候选 | 1944.332 |
| 恢复资源范围基线 | 1930.183 |

该对样本没有体现收益，撤回。它只是 A/B 初筛，不是所有轮询策略的稳定负收益证明。
机器码确认空转消失，但无记录 AIC/AIV 函数从 222924/222232B 增至 227316/228956B；
不能把源码减少当作热函数缩小，也不能把尺寸变化直接归因为测得的时间差。
该候选未扩展到完整设备故障矩阵，没有补采 L3。

新增 90 项等待场景在原实现上有 36 项“退避耗时必须为零”的策略 RED、54 项通过；
首次夹具编译中的枚举拼写错误另有日志，不把它当作业务 RED。
候选通过后撤回零退避策略断言，保留全部 90 项迟到 Ready、EXIT、错误及不误领取的保护。
保留版仍采用原调度期和启动屏障退避。

## 显式无记录执行边界：保留局部检查点

改动只在现有模板中把 task timing、原生执行记录路径与 `WithProfiling` 对齐，
并仅在启用阶段记录时读取退避计时的两个时钟。没有新增环境变量、宏或用户开关。
业务调用、原子强确认、实际资源的 ARRIVED/RELEASED、错误检查及共享 ABI 均不变。

每批三轮七项 golden、5 次预热、100 个正式样本，同卡 A/B/B/A：

| 批次 | 完整 Device 中位数（us） |
| ---- | ------------------------ |
| A1 候选 | 1919.790 |
| B1 基线 | 1926.077 |
| B2 基线 | 1926.354 |
| A2 候选 | 1923.272 |

每臂 200 个样本，合并中位数减少 4.566us，约 0.237%。两批候选均低于两批基线，
但差值很小，不保证每次调用或其他负载都能得到相同收益。
54 个链接后业务 kernel 指纹一致，全部正式样本保留；四批没有其他 A5 CLI 重叠观察，
正式采样与本会话的编译、其他设备测试和设备查询分开。没有任务锁，不称系统级独占。

无记录 AIC/AIV 函数为 217564/224588B：AIC 变小、AIV 略大，不能只报告有利的一侧。
每个函数的静态 `SYS_CNT` 位置由 97 减至 88；这是静态位置数，不是每次循环都少执行九次读取，
也不是 I-cache 缺失或耗时占比。本轮没有声称已测得分阶段的 I-cache 收益。

## 回归结果与干扰限制

新增等待保护覆盖三 lane、L0–L4、有无准入以及迟到 Ready／EXIT／错误；
另补六项 L3 采样身份检查。入口目标共 129 项，在基线和候选上都通过，不伪称旧业务缺陷。
候选 21 个 C++ 目标、3989 项 HBG Python 检查、563 项 CSA／读取器检查及静态检查通过。

- 真机常规回归：88 通过、4 跳过、4 deselected；CLI 重叠观察为零。
- 真机故障：58 项全部通过，源码和三件二进制前后相同，但有 239 次其他 A5 CLI 重叠观察。
  这份成功结果保留为实际运行证据，不称独立／独占故障验收，也不作为性能样本。
- 首次 SPMD 因其他会话使用 device 0 被预检查拒绝，未执行；原日志保留。
  另一次聚合测试通过，但有一次其他 A5 CLI 重叠观察，同样不称独立验收。
- 仿真常规：67 通过、29 deselected；故障 46 通过，12 项不可返回 kernel 场景按既有规则仅在真机执行；
  SPMD 聚合测试通过。

严格 L4 通过 2308 个执行身份、133 条依赖、3808 个成员义务和 40193 个事件，两轮七项 golden 通过。
独立 L3 的七项 golden、完整身份和依赖检查通过，kernel 窗口 1829.051us，全员计算空窗 510.207us。
L3 使用有记录模板，不能用它精确分摊无记录版本的收益；全员无 kernel 也不等于 Scalar 全部空闲。
最终版本仍须按总计划完成目标性能和回归审计，不能用本轮有干扰的功能检查冒充独立最终验收。
