[返回当前结论](2026-11-a5-swa-ordinary-pool.md)。以下记录各历史候选的当时结果与撤回状态。

## 验证与计时

候选原生身份格式 v2 明确记录 `pool / ordered / single`，原生协议 v10 增加池发布、
确认、退休和完成证据，没有伪造准入序号或放宽旧格式。实际 A5 L4 严格审计通过：
96 个 worker、24 个执行任务、517 个 block、549 次执行，五项原始 golden 全部通过。
成员义务从 1344 降至 96，事件数从 8674 降至 6178；这些减少没有转化为计时收益。

候选通过相关 C++ 原语、布局、分派、准入、Mix 和导出检查，以及 1132 项 Python
解析/审计测试。实际 C++ 调度验证四种 Mix 组合抢占已准备的池 block，并完成退出。
AIC/AIV 原生编译通过。未运行候选完整仿真/硬件回归和完整故障矩阵。

## 恢复与后续边界

候选的源码、测试、解析器和原生运行库均撤回；只撤回本候选，保留此前验证过的修改。
恢复后的源码差异哈希与冻结 `idle-nop1024` 一致，所有归档原生文件哈希、接口、runtime pin
和默认 RuntimeBuilder 的 PTO-ISA 校验通过。恢复后的 6 组 C++ 测试、1025 项 Python 测试通过。

期间修正过的候选边界也随候选撤回：多 block predicate 与非法 LaneMask 分类、GM 到 Local
的 LaneMask 复制，以及原 single-subtask helper 遗漏 AIV1 的问题。不能称这些已在保留版本修复。

归档在 `$DEV_ROOT/logs/swa-hbg-opt-20261101/`：`ordinary-pool-only.patch`、
`ordinary-pool-archive/`、`frozen-bundles/ordinary-pool/`、`ordinary-pool-profile/`、
`frozen-ordinary-pool-abba/summary.json` 和 `restored-after-ordinary-pool.json`。
`audit-frozen-ordinary-pool.py` 验证归档审计器的哈希，再独立复核原始 L4；恢复后已复核通过。

若重开，必须改变实际开销机制并做隔离对照。候选的高频全局位图原子观察、重复形状检查、
额外代码和预取行为都可能影响耗时，当前没有测量把 33.24% 回退归因于其中某一项。
应优先检验分散发现任务的原子观察或复用不可变任务信息，保持同类型所有核的资格、
有界发现、入口检查和真实协议证据；不能仅以更少的成员义务再次宣称应当更快。

## 后续隔离对照：Ready 优先与单次填槽内观察复用

两项后续候选均未达到保留门槛。每项采用同设备的 `ABC/CBA/BCA/ACB` 四组对照，
每批仍是 5 次预热、100 次正式样本。各候选的完整业务字节、64 个生成源文件、接口、
输入和五项 golden 比较均相同；每项十二批均通过数值检查，计时期间未并行编译。

### Ready 优先

原领取池在已有 Ready kernel 时仍可能继续准备普通 block。本候选只让这一准备动作
让位于已有 Ready；任务发布与协作任务发现仍执行，未改变共享状态访问方式。
七项新增实际分派测试先在原候选上失败，再在修改后通过；相关五组 C++ 测试通过。
旧 L4 中没有发现同任务的 slot 1 被后来准备的 slot 0 超越，因此不能把原回退归因于
已证实的槽位饥饿。

## 后续隔离对照：复用已观察的正发布位

第三项后续候选基于填槽内观察复用，只消除预留时对已观察正发布位的重复原子读取。
观察对象的字段封装为私有，只能由真实原子观察填充；预留检查地址、epoch 和对应任务位，
空观察、负观察及不匹配的观察均拒绝。生命周期仍限于同次填槽，Graph 复用仍不启用此路径。

安全依据是同次运行内发布一次、退休一次且任务身份不复用：曾读到正位证明此前已经发布；
退休要求所有合法 ticket 已预留并确认，因此新的领取游标检查会拒绝退休任务。
发布标记仍重新原子读取，ticket 仍原子领取，确认、完成及入口检查保持原有规则。
未携带观察的通用预留调用仍执行完整位图读取。这里没有把正发布事实当作剩余工作或执行许可。

参考依据包括 atomic 指南的 atomic-only 控制状态和生命周期边界，以及优化记录
15.65–15.70 中“复用证明或减少原子次数不自动等于端到端收益”的经验。
四组相关 C++ 测试通过，包含过期正观察、负观察、不同字/地址/epoch、损坏发布标记和
双线程 exactly-once；实际 A5 L4 的 549 次执行、517 block、96 worker、22 个池任务
和五项 golden 均通过。未执行该候选的完整仿真/硬件故障矩阵。

按真实运行库的 CCEC 参数编译两种预留入口的小探针，在 AIC 和 AIV 中均得到
完整读取 4 个、正观察复用 3 个 `ATOM.ADD.u64` 指令点。该结果只确认探针代码生成，
不代表运行中的动态总数；完整运行库反汇编另存，其内联调试行信息不足以单独定位该调用点。
构建冻结时，默认 PyPTO 校验使旧生成二进制缓存失效并重建；重建后的完整业务字节与
两个对照版本仍完全相同，64 个生成源文件与接口哈希也相同。

## 后续隔离对照：空探测后只延后一次

参考优化记录 15.1–15.4 的有限降频经验，在正发布位复用版上试验一个私有布尔标记：
一次填槽尝试探测领取池、且没有 Ready/准入/领取进展时，下一次填槽只跳过新池任务探测，
随后必须重试。有实际进展就取消延后；已有预留和协作任务服务照常进行。延后判断仍位于
错误、epoch 和普通入口前沿检查之后。标记复用原有 padding，本地准入状态仍为 400B，
没有改变共享布局、原子交权、计数规则或跨填槽缓存位图观察。

三个 lane 的迟到远端发布测试先在前序版上失败，再在候选上通过，证明实际分派路径实现
`空探测 -> 跳过一次 -> 重试领取`。另外覆盖取得进展后连续领取、协作准入、错误/epoch、
已有预留执行和初始化清除预算。五组相关 C++ 测试通过，补充后的 ordered-execution
目标全部 222 项通过。原生 AIC/AIV 编译和 400B 断言通过，未插桩 resident idle NOP
循环反汇编仍无 load/store。实际 A5 L4 的完整 549 次执行、517 block、96 worker、
22 个池任务及五项 golden 均通过。未执行该候选完整仿真/硬件故障矩阵。

## 测试目标恢复后的补验说明

原生 L4、golden 和冻结计时证据未受影响，候选的性能否决结论不变。后续检查同时核实目标
重新编译和实际执行的测试名称/数量，不以退出码或 0 项测试通过作为证据。
