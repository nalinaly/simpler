# A5 SWA 领取池位图粒度对照

[返回当前结论](2026-11-a5-swa-ordinary-pool.md)。以下记录粒度实验，最终启动修复与停止状态以当前结论为准。

## 16 任务位图字：初步改善，尚未保留

在正发布位复用版上，将每个原子字覆盖的任务数从 64 改为 16，位图字仍独占 128B。
每核初始私有游标由 worker id 对任务数取模，随后继续原有有限轮转。所有同类型 worker
仍可领取所有普通任务，没有固定配额，也没有带入已撤回的空探测延后策略。
SWA 的 34 个任务使每个引擎从一个字增至三个字，总计增加 512B。更细的字需要更多
探测才能绕完一轮，因此地址分散与发现延迟必须共同计入完整耗时。

参考优化记录 15.54 的 128B 地址冲突经验及 atomic 指南的 atomic-only 控制字原则，
这里没有新增 LDDEV/STDEV/DCCI 交权。参考芯片的物理冲突结论仍只作为假设依据；
本轮同时改变粒度和初始扫描相位，没有单独区分两个子变化的贡献。

图摘要保持 128B，原有 104 偏移的 64 位拓扑字段保持不变。已受 INT32_MAX 限制的
池任务数改为 112 偏移的 uint32，116 偏移存每字任务数，位图偏移仍在 120。
主机初始化在任何写入前拒绝不可表示的计数；设备启动要求池映射恰好为 16、无池时为 0。
旧设备代码会把非零映射与任务数组合读成不可能的大计数，并按原有上界检查拒绝。
审查中放弃了把映射放进拓扑字段高半部的草稿，因为旧 AICPU 可能整块覆盖该字段；
该草稿没有构建成原生运行库或上板。

原生格式 v11 明确导出实际摘要的 `word_task_capacity`。解析器检查容量、字数、
退休位及同字邻居关系，保留 v1–v10 的原有规则，拒绝把 v11 记录伪装成 v10。
9 组 C++ 测试、1180 项 Python 测试及相关 lint/格式检查通过；真实 v8 与 v10 旧捕获
也经新解析器独立复核通过。实际 A5 v11 L4 确认每引擎 3 个字、终态 6 个字全零，
549 次执行、517 block、96 worker、22 个池任务和五项 golden 全部通过。
原生 AIC/AIV idle NOP 循环仍无 load/store。候选尚未运行完整仿真/硬件回归与故障矩阵。

| 对照组 | A：idle-nop1024 us | B：正发布位复用 us | C：16 任务位图字 us |
| ------ | -----------------: | -----------------: | ------------------: |
| ABC | 896.3120 | 918.6710 | 875.8345 |
| CBA | 857.4500 | 908.0435 | 874.1310 |
| BCA | 918.3485 | 909.1115 | 890.5705 |

同设备冻结对照保持完整业务字节、64 个生成源文件、接口、输入与容差不变，每批
5 次预热和 100 次正式样本，十二批数值检查均通过，期间无本实验并行编译。
C 相比 B **4/4 更快**，组内改善中位数 **3.3351%**；相比 A **3/4 更快**，
组内改善中位数 **1.6638%**。这是待复核的改善，尚不能宣称稳定超过保留基线，
更没有证明超过 TMR。该轮先恢复保留版本，同时保存候选供下一组受控比较使用。

归档为 `pool-word16-archive/` 与 `frozen-bundles/ordinary-pool-word16/`。证据包括

结果见下一节。任何候选在保留前仍需要稳定性能证据、适用的完整回归和同条件 TMR 对比。

本轮恢复后，8 组 C++、1025 项 Python 测试及归档 v11 L4 的独立复核通过；
记录为 `pool-word16-restored-*.log` 和 `pool-word16-archived-audit.json`。

## 32 任务字对照与 16 任务版复测

32 任务版的运行库源码相对 16 任务版只有容量常量这一处变化，初始游标、领取资格、
入口检查和完成规则相同。v11 解析器明确支持 16/32 两种映射，设备启动仍只接受其编译
容量。通用化后的 C++ 边界测试先在原样的 16 任务源码上通过，再验证 32 任务版本；
32 任务版的 9 组 C++、1228 项 Python 检查通过，真实 v8/v10/v11-16 旧捕获复核通过。
实际 v11-32 L4 确认每个引擎两个字、终态四个字全零，完整 549 次执行、517 block
以及五项 golden 通过。候选未做完整仿真/硬件回归。

| 对照组 | A：idle-nop1024 us | B：16 任务字 us | C：32 任务字 us |
| ------ | -----------------: | --------------: | --------------: |
| ABC | 896.7295 | 872.8350 | 895.1660 |
| CBA | 904.0140 | 887.9545 | 896.8585 |
| BCA | 852.4065 | 874.6575 | 901.5530 |
| ACB | 920.3210 | 886.9820 | 893.3010 |

使用同设备、冻结完整业务字节、64 个相同生成源文件和原始输入/容差，每批 5 次预热、
100 次正式样本。十二批数值检查通过，计时期间无本实验并行编译。
32 任务版相对 16 任务版 **0/4 更快**，组内回退中位数 **1.7806%**，故撤回。
其相对保留基线虽为 3/4 更快，改善中位数仅 0.4829%，也没有理由取代更快的 16 任务版。

16 任务版本轮相对保留基线 **3/4 更快**，组内改善中位数 **2.2205%**；前一轮为
3/4 和 1.6638%。两轮方向一致，但各有一组回退，不能把合并的逐轮样本当独立重复或
宣称已经证明稳定收益。选择 16 任务版进入更广回归，正式保留决定仍待后续证据。

再用同设备进行 TMR / 16 任务版的 `ABBA` 直接对照，每批仍为 5 次预热与 100 次正式样本，
四批全部通过原始数值检查：

| 配对 | TMR 完整 Device 中位数 us | HBG 16 任务版 us | HBG 多耗时 us |
| ---- | ------------------------: | ---------------: | ------------: |
| 1 | 647.0425 | 876.8130 | 229.7705 |
| 2 | 638.5275 | 876.7280 | 238.2005 |

配对差距中位数 **233.9855 us / 36.4078%**，HBG 尚未超过 TMR。这不是与历史最小值
比较，也没有从插桩阶段累计耗时中减出所谓可回收墙钟时间。

32 任务版保存在 `pool-word32-archive/` 和 `frozen-bundles/ordinary-pool-word32/`；
主要结果是 `pool-word32-profile/audit.json`、`frozen-pool-word32-three-arm/summary.json`
和 `frozen-tmr-word16/summary.json`。先恢复 `idle-nop1024` 后，再校验归档哈希并装回
精确的 16 任务源码和原生运行库供回归使用，记录为 `installed-word16-for-regression.json`。

更广回归的逐阶段状态保存在 `pool-word16-regression-progress.json`：先显式配置并重建
全部 A5 HBG C++ 目标，再构建 a5sim，最后运行默认 manual/platform 选择下、低于 L4 的
HBG 仿真用例。CPU 限制为两个核，编译并发不超过 2，ctest 单目标并发。
仿真聚合会话预算为 1200 秒，以容纳受 CPU 限制的整批检查；未修改单用例或运行库 watchdog。
硬件回归仍需在仿真检查之后通过设备队列执行，不能把当前的 SWA L4 通过当作它已完成。

本轮更广检查已完成全部 100 个 A5 HBG C++ 目标，全部通过；a5sim 构建也通过，
新增仿真库后板上运行库文件哈希仍匹配冻结 16 任务版，两个平台的默认 PTO-ISA 校验通过。
首轮仿真套件已结束：90 项通过、2 项跳过、9 项失败。硬件套件尚未开始。
