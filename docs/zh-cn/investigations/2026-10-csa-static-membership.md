# CSA 准入成员表前置：完整设备收益不足以支持保留

日期：2026-10-30。两个候选的运行时代码与候选策略测试均已撤回。
当前保留 `d19885ded` 的实际资源范围协调：1C1V 两 lane，1C2V 三 lane，
所有合法 cluster 继续公平竞争。完整 Device 约 1.926ms，尚未达到 1.5ms。

## 问题与假设

资源范围版 L3 的 kernel 窗口为 1829.802us，全员无业务 kernel 的空窗合计 521.674us。
12 段可顺序拆分的大交接空窗合计 289.560us，其中 Resolve 结束至首块准备为 152.860us；
这是全部空窗的子集，不是全图耗时分解。t56 的扇出发布与 Resolve 重叠，不能强行串行相加。

参考 `simpler_dev/tests/atomic_probe/pa_scheduler/cross_core_only_scheduler/README.md`
在 Host 准备不可变执行镜像的思路，尝试前移本次运行不变的准入成员 bitmap、成员数和 epoch。
不照搬旧 demo 的固定 G1、subblock=0、只读 context 或零拷贝参数前提。

两版都不改变任何 cluster 的竞争资格、全局准入顺序或固定 C/V 端点。
必要资源 lane 全部 ARRIVED 才进入 kernel，全部 RELEASED 才复用 mailbox；
动态 phase、claim、完成计数、错误门禁、epoch、generation 和记录身份检查仍保留。
普通多 block、sync_start、原样 CSA 的 54 个 kernel、2308 个执行身份和七项 golden 不变。

## 两个候选

第一版由 AICPU 在真实核心发现后、发布 READY 前构造成员表。
Scalar 准入时核验预先构造的精确集合，不再重新写回成员表；
扫描准入日志时仍 acquire 动态 header，但不逐次失效不可变 bitmap 所在行。
启动入口原有整 cache 观察负责取得 READY 发布前的不可变数据。

这一版只是把工作移到了仍受完整 Device 计时覆盖的 AICPU 启动阶段，不能把它当作消除了成本。
初筛候选 1935.2000us、恢复基线 1923.1315us，候选慢约 12.1us。
不把这一对样本外推为稳定负收益。

第二版由 Host 在既有 HBG 准备阶段生成计划成员表，AICPU 对实际发现的拓扑逐项核验；
不一致就拒绝 READY，不静默覆盖原表。Host 生成后清除临时计划拓扑身份，
防止发现前失败时把计划 cluster／lane 错报成实际发现结果。
两版的 AICore 二进制相同，区别在 Host/AICPU 准备与核验路径。

该静态分离没有前移每次执行的领取、依赖推进、组协议或输出可见性工作。
但它新增了 Host 计划拓扑构造、成员镜像和 AICPU 核验路径，不能只按少几次 Scalar 写回来判断取舍。

## 完整设备测量及无效批次

每个计时批次先跑三轮七项 golden，再以 L0 运行 5 次预热、100 次正式采样。
以下是未观察到其他 A5 CLI 重叠的有效批次；全部 100 个样本保留。

| 版本与批次 | 完整 Device 中位数 us | Host 中位数 us |
| ---------- | --------------------- | -------------- |
| AICPU 构造候选 A1 | 1935.2000 | 139137.0090 |
| 对应恢复基线 B1 | 1923.1315 | 78708.8950 |
| Host 构造候选 A1 | 1915.7085 | 78775.6755 |
| 对应恢复基线 B1 | 1922.4410 | 137661.9670 |
| Host 构造候选 A2 | 1919.2300 | 78891.4265 |

Host 构造候选比有效基线分别低 6.7325／3.2110us，即约 0.35%／0.17%。
这不是稳定负收益，但也不是足够强的保留依据。Host 批次波动明显，
总 Host 时间包含既有编排、准备和校验；没有单独为成员表准备打点，不能将这些差值归因于预计算。

原本准备做反向对照，但中间的 `idle-host-members-b2` 出现另一进程使用同一 device 0，
监测器记录到 96 次重叠观察。该批 Device 中位数为 1923.111us，
即使数值看起来接近基线，也整批排除出比较，不把它补入合并中位数。
原始 100 个样本、通过的 golden、失败的隔离检查和重叠日志全部归档。
另外两次基线启动在检测到设备测试后直接拒绝，未产生计时样本。
因此本轮没有完成有效的 A/B/B/A，不能把三批有效结果包装成四批对照。

正式采样没有并行本轮编译、回归或设备查询；CLI 监测也不是全系统独占证明。
回测基线时源码树保持候选，实际加载的是 `d19885ded` 已验收的三件 runtime 归档。
证据按二进制摘要区分，不能仅根据工作树 diff 推断测量臂。

## L3 没有显示宏观瓶颈已解决

三份独立捕获均检查逐 block 身份、依赖、七项 golden 和记录无丢失：

| 版本 | kernel 窗口 us | 全员无 kernel us | t23 同 cluster 组间间隔中位数 us |
| ---- | -------------- | ---------------- | -------------------------------- |
| 已保留资源范围版 | 1829.802 | 521.674 | 15.7645 |
| AICPU 构造候选 | 1818.476 | 528.571 | 16.0710 |
| Host 构造候选 | 1807.230 | 516.500 | 15.8485 |

不能用较短的单次 kernel 窗口替代完整 Device 对照，也不能把独立采集的差值当作精确因果贡献。
Host 候选仍有约 516.5us 全员无业务 kernel 区间，t23 的约 15.8us 组间间隔没有改善。
t23 的不同 cluster 交错执行会掩盖组间等待，只盯全员 idle 会遗漏这一成本。
全员无业务 kernel 不等于 Scalar 全部空闲，组间间隔也不能直接归给某一个 helper。

## 验证范围与撤回

- AICPU 构造版：新增 4 个真实生命周期接线测试在基线 RED，原有 7 项通过。
  覆盖 1／2／22／32 个 cluster、三种 epoch、全部非零 mask 和跨 64 位 bitmap 边界。
  这里是成员表构造层的覆盖，不据此扩大公共提交入口支持的任务形状。
  候选 21 个 C++ 目标与 3989 项 Python 合同／读端检查通过。
- Host 构造版：4 个“核验预生成成员且不得修改记录”的行为测试在前版 RED，
  新版 21 个 C++ 目标通过。覆盖损坏的成员集合、不得重置证据和发现前未知拓扑身份。
  成员构造还覆盖非法计数、偏移、拓扑、metadata、seal 行及失败不产生部分写入。
- 两版 A5/A5sim 构建成功，严格 CSA L4 均通过 2308 个执行身份、133 条依赖、
  3808 个成员义务、40193 个原生事件及两轮七项 golden；不放宽 v8 审计。
- Host 版没有重复整套 Python 检查；两个候选都没有扩大到完整 HBG 设备／故障矩阵。
  不能把上述局部验证表述为完整发布验收。
- 撤回后运行时源码恢复至 `d19885ded`，A5 三件套恢复并核对摘要，A5sim 重新构建，
  21 个 C++ 目标重新通过。新增候选策略测试随候选归档，不留死接口。

取舍是“几微秒初筛领先不足以支持新增准备镜像路径”，不是声称 Host 静态准备没有价值。
当前不通过新增这一层复杂度换取尚未确认的微小收益，也不把候选约 1.916ms 报成已保留成绩。
