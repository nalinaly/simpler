## 关键调度链路

L3-b 的典型全员空窗可进一步拆为以下连续区间，单位为 us：

| 前驱至后继 | 末 kernel 至 Resolve | Resolve | Resolve 结束至首块准备 | 首块准备至 kernel |
| ---------- | -------------------- | ------- | ---------------------- | ----------------- |
| t22 至 t23 | 4.524 | 2.642 | 14.975 | 3.366 |
| t23 至 t24 | 5.805 | 3.136 | 11.055 | 4.092 |
| t31 至 t32 | 1.877 | 4.147 | 15.585 | 3.850 |
| t45 至 t46 | 2.158 | 3.819 | 14.968 | 4.119 |

后继启动前的长等待不能全归给 Resolve。准入、成员推进与组启动需要作为完整链路审视。
扇出前缀可能在 Resolve 结束前发布，不能把所有转换强行套成互不重叠的串行四段。

t23 的 512 个 Mix block 分到 32 个 cluster，每个有效核执行 15–17 次，分配较均衡。
组内 kernel 包络中位约 6.85us，同 cluster 的组间间隔中位约 16.99us，启动周期约 23.89us。
最后完成 cluster 的跨度恰为 1.953us 首块偏移、121.673us kernel 包络、265.279us 组间间隔。
该任务全局空窗只有 8.818us，因为不同 cluster 的等待错开；仅看全员 idle 会漏掉这个大头。
L1 的同类组间间隔中位仍为 15.5765us。

t56 后 16 路输出投影拥有共同的数据前驱，但首块启动分散在 198.734us 内。
pack 自身跨度中位 3.9765us，父投影返回至 pack 首块中位 129.333us。
这些等待大量重叠，不能相加为可省时间；最后投影返回至全部 pack 完成只有 67.547us。
N=8 Mix 的成员集合仍为 96 个 worker，N=4 Vector pack 仍为 64 个 AIV。
成员推进不是全体同步启动，也不是全局完成屏障，本实验不改变这套成员合同。

t105 的最后完成 cluster 中，kernel 包络 161.293us，组间间隔 19.186us，首块偏移 7.476us。
其约 188us 跨度主要来自业务执行，不作为固定 kernel 条件下的首要优化对象。

## 跨类型直接准入：撤回

### 候选机制

协同后继已满足依赖时，resolver 若有一个空闲持久候选槽，可直接保留该后继，
不再要求后继执行类型与 resolver 相同；随后仍经原 discovery 分类、准入和 block 领取。
普通 N=1 跨类型后继仍入 Ready 队列，候选额度耗尽也回退入队。
保留唯一所有权、完整依赖检查、两份候选额度、错误门禁、成员集合和三 lane Mix 协议。
准入发起者可以是 AIV，但 Mix block 的协调者仍是其固定 C，不把准入等同于执行许可。

代码复用原 `scheduler_task_requires_admission` 判定，增加标量参数入口，避免把 GM 引用
绑定到 Local Memory 参数；首版原生编译地址空间错误及修正日志均保留。
一项旧测试的“必须入队”断言改成“私有候选唯一持有、准入后执行”，
原有等待最后组、inactive C 协调、完成计数及两次物理执行检查不删除。

原生记录确认机制实际生效：基线 26 个 Mix 全由 AIC 准入；候选 20 个由 AIC、6 个由 AIV 准入。
因此不能将后面的无明显收益解释为分支未命中。

## 后序 pending 不阻塞当前义务

### 顺序证据与合同

原 `scheduler_ordered_can_enter_slot` 在区分普通槽／当前协同槽之前，统一拒绝持有 pending 的核进入。
这把“未提交的后序候选 B”也当成了“当前 A 之前必须完成的责任”。
但当前 A 已在日志提交前缀；CLAIMED／PREPARED 的 B 尚无序号，只能在未来追加到 A 后面。
因此 A 通过当前身份、组 generation、资源与错误检查后，可以先执行。
普通单 block 仍必须完成 pending 发布并重新确认前缀，不采用这个例外。
全局短提交锁只在有限提交函数内持有，返回 RETRY 时没有获得锁；不是允许持锁进入 kernel。

保留所有合法 cluster 的竞争、固定 C/V 放置、两／三 lane 的完整 ARRIVED／RELEASED、
唯一 block 所有权、epoch、TaskDone 与失败门禁。没有新增开关、字段或 ABI，业务输入和 kernel 不变。
这不涉及“部分必需 lane 到达就启动”，也没有实现双缓冲 mailbox。

基线严格 L4 找到 4 个执行槽：payload 已发布后，同核先完成 5 次后序准入，再进入当前 kernel。
对应 A→B 为 t21→t22、t36→t35、t48→t49，以及同一个 t79 执行槽中的 t73／t88。
按 order_key 判断前后，不能按 task ID 大小排序。其 READY 至 entry 为 12.340–21.606us；
这些有重叠的窗口不能相加，也不能认定全部由该门禁造成。候选捕获未再出现这种模式。

### 完整 Device 对照与 L3 限制

同卡串行 A/B/B/A，每批三轮七项 golden、5 次预热、100 个正式样本：

| 批次 | 完整 Device 中位数（us） |
| ---- | ------------------------ |
| A1 候选 | 1891.1065 |
| B1 基线 | 1908.0910 |
| B2 基线 | 1899.6640 |
| A2 候选 | 1895.9045 |

两臂各 200 个样本，合并中位数相差 10.2915us；两批候选均低于两批基线。
所有样本保留，54 个业务 kernel 指纹相同；计时没有并行本会话的编译、其他测试或设备查询，
没有其他 A5 CLI 重叠观察，但这不是系统级独占证明，也不是五批目标验收。
差值小，不保证每次调用或其他负载得到同等收益。

候选独立 L3 的 kernel 窗口为 1817.804us，全员无 kernel 空窗为 534.851us。
前一检查点分别为 1836.804／517.459us：总窗口缩短，但全员空窗反而增加。
t23 完成至 t56 完成区间的空窗为 302.964us，与前次 303.252us 基本相当。
因此不能把这次局部 Device 改善说成消除了主要宏观空窗；L3 也不能精确分摊 L0 的收益。

另外复核两份既有 L3，每份 536 次同 task、同 cluster 的连续 Mix 交接中，
C 完成自身 Complete 阶段后，同组 V kernel 均已结束。仅按 kernel 返回计的 C 提前量中位
为 0.178／0.181us；计入 C Complete 后，观察到的重叠窗口均为零。
Complete.end 还早于 trace 写回及 RELEASED，因此这是偏乐观的窗口估计。
这不支持靠“C 收尾后准备下一组与同组 V 计算重叠”取得大收益；
它不排除其他流水化机制，不证明无插桩窗口严格为零，更不能把各 cluster 等待相加成 wall-time 收益。
