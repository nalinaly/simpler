# A5 SWA 普通多 block 领取池：原版回退与后续对照

**Date**: 2026-11-02
**Verdict**: 原版、前四项后续候选及 32 任务位图字版已撤回。16 任务版两轮均有初步改善，
其启动修复版完成完整仿真和 SWA 板上审计，尚未正式保留。已验证的回退点仍是
`idle-nop1024`；修复版与 TMR 的最新直接对照慢 37.03%，最终目标未达成。
按用户要求，本轮对照完成后停止，不继续优化或剩余硬件回归。

## 实验与约束

DeepSeek V4.1 Flash 的完整 SWA 路径有 24 个执行任务、517 个 block、549 次 kernel 执行。
其中 22 个普通单 lane 多 block 任务贡献 477 次执行；另一个 sync-start 任务和一个 Mix
任务贡献 72 次执行。这个组成不同于旧 CSA 领取池实验，因此单独验证，未移植旧实验的收益估计。

候选把普通任务移出共同准入日志，以两类全局原子位图发布，所有同类型 worker 均可竞争。
每次发现只观察一个位图字，私有游标轮转；预留、确认和完成分别计数。
候选槽保留被抢占 block 的身份，入口把预留记录转交给执行槽，完成后才释放。
Mix 与 sync-start 保留原有准入和 ARRIVED/RELEASED，普通入口仍检查当前前沿、错误和 epoch。
有 Graph binding 的调用保持原路径；没有新增环境变量、行为宏或固定核配额。

按 `simpler-fdwic-swimlane-deps/tests/atomic_probe/ATOMIC_USAGE_GUIDE.md` 审查共享状态：
新位图字使用 128B 隔离和原子访问，不新增 LDDEV、STDEV 或 DCCI 控制交权。
一位在同次运行内只发布和退休一次，故原子加该位及减该位分别实现置位和清位。
原语测试覆盖三个任务全部 90 种合法发布/退休交错、第 63 位、双线程唯一领取和延迟确认。
这项布局论证不替代当前芯片实测，也不替既有运行库中的 bypass 信号和整个缓存操作背书。

## 纯 pool 启动修复与故障回归

五项 SPMD 失败在独立运行中复现。真正的启动入口只在 `admission.capacity != 0`
时挂接本地调度状态；只有普通 pool 任务时，协作容量为零，实际只执行 block 0 并错误地
完成整个任务。SWA 图中有 Mix 和 sync-start 任务，因而之前的 SWA 原生验证没有覆盖该条件。

修复让非空 pool 同样挂接已经校验的本地状态，没有改变共享状态或原子协议。
新增真实启动入口回归覆盖 AIC、两种 AIV worker，以及开启/关闭 L4 两条路径，要求八个
block 各执行一次并正确完成。六组用例在修复前均只执行一次，修复后通过；整个启动测试
目标的 135 项通过。五项失败的 SPMD 仿真检查随后通过，包括跨目录分片分布检查。
新源码摘要为 `35a84eef2c3a3d107fda59f12a0b8ad455e386f8d59099b1ad194cd1b6b6eeb1`，
不能把旧冻结版本的计时直接算作新构建的结果。

另外三项故障测试在健康阶段仍硬编码 v8；纯 pool 的实际导出为 v11。测试现按任务形态
选择格式，增加失败状态的严格 wire 读取、唯一发布者、原子 ownership 标记、确认序号、
剩余位图及最终确认者退休证据检查。未完成领取允许保留对应位，不允许把失败现场
强制当成成功终态。失败后禁止 consumer 执行、拒绝重提交、保留借用缓冲区和恢复检查继续执行。

257-block Mix 的健康阶段在两个 CPU 核限制下超出两秒。在同一 checkout 恢复保留基线、
重新构建 a5sim，并保持相同 CPU 亲和性、用例和时限，也复现了该超时；随后恢复候选的
精确源码及仿真库。健康诊断在十秒预算下约 3.14 秒完成，数值和协议审计通过。
仅此仿真用例使用六秒 watchdog、八秒注入停顿，仍验证 watchdog 先于停顿返回、失败隔离
和恢复。硬件时限不变。意外健康运行错误也会关闭 Worker，避免缓冲区释放错误掩盖原异常。

修复后的八项 resident failure 仿真用例全部通过。主要记录为
`pool-word16-startup-red.log`、`pool-word16-startup-green.log`、
`pool-word16-startup-sim-tests.log`、`mix-timeout-baseline-control.json`、
`mix-healthy-budget-diagnostic.json` 和 `pool-word16-startup-failure-sim-tests.log`。
新版本完整仿真已完成：99 项通过、2 项跳过、无失败；相关额外执行器 C++ 两个目标通过，
新增部分失败记录检查的 21 项 Python 用例通过且无警告。板上版本重新构建并冻结为
`ordinary-pool-word16-startup`，与保留基线及父版本的完整业务字节、64 个生成源码、
native interface 哈希一致。默认 a5/a5sim PTO-ISA 校验通过。

新冻结版本在 2 号设备的 SWA L4 原始 golden 和严格协议审计通过：96 worker、6178 个
事件、24 个执行任务、549 次执行、517 个 block，477 次 pool 和 72 次 ordered 执行。
记录为 `pool-word16-startup-profile/audit.json`。完整硬件回归已通过队列在 2、3 号
设备启动，默认选择 220 项、最多两个并行用例且各限一个编译 worker。完整硬件结果及
新冻结版本的原生性能复核在该阶段尚未完成。

## 按用户要求完成最终对照并停止

用户将本轮终点限定为“用新冻结版本重新对照 TMR 就停下来”。因此停止继续派发硬件
回归用例，等待当时两个用例自然以 exit 0 退出，再终止本任务的调度进程并释放设备。
已闭合的硬件日志有 26 项通过、7 项跳过、无失败；另两个自然退出用例没有归入闭合日志
计数。完整 220 项未跑完，不能记作全部通过。

使用新冻结 `ordinary-pool-word16-startup` 与 `tmr-current`，在同一 2 号设备按
`ABBABAAB` 执行四组配对。每批 5 次预热、100 次测量，保持原始输入、容差和全部样本；
60 个计算/PTO/PTOAS 源文件哈希相同。八批数值校验全部通过。
