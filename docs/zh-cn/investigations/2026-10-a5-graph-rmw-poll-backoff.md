# A5 Graph：仅给共享 atomic 热轮询增加小退避不足以消除长尾

日期：2026-10-30。结论：**不采用“保持全员 RMW 轮询，只增加已有 8→32 次本地退避”作为独立修复**。完整数据及后续方案见[性能/资源调查](../a5-hbg-aicore-graph-p4-performance.md)。

## 问题与候选

`81cb66774` 的原生 Graph 在 A5 上数值正确，但小 AIC/AIV、Mix Graph 的 L0 启动出现毫秒到秒级尾部。旧 AICPU Graph 对照没有同等级长尾；冻结 CSA 两版基本持平。

L2 将等待定位到 context 发布之后、kernel 放行之前。第一个候选复用 resident ready 屏障的有界本地退避，仍由全部 worker 在 `remaining_instances` 上反复 `atomicAdd(0)`；没有减少参与核或改变计算任务。

## 实测与决定

每组候选运行 305 次，丢弃前 5 次预热，300 个稳定态样本全部数值通过：

| 用例 | Device P50 µs | P99 µs | 最大 µs | >5ms 次数 |
| ---- | ------------- | ------ | ------- | --------- |
| AIC/AIV Graph | 196.9 | 364.5 | 17,086.6 | 2 |
| Mix Graph | 356.9 | 1,038,598.0 | 3,041,941.3 | 22 |

这批同时运行 CPU 仿真回归，因此不把 Host 时延用于优化判断；Mix 的秒级 Device 长尾仍明确存在，足以拒绝“该候选已经解决问题”。记录在本地 `outputs/graph-backoff-trial.zPTegK/`。

保留该候选的 L3 捕获再次复现约 3.199s：所有 worker 约 3.198s 后才进入 ready bootstrap，ready 扫描和初始准备本身只用 18–39µs。失败证据不是只有一个汇总最大值。

后续改为隔离行的单 writer bypass 发布信号，保留 atomic 完成计数和等待端最终确认。小本地退避可以作为信号探测节奏保留，但它不再被称为消除长尾的独立优化。具体硬件队列/仲裁原因没有单点测量，不以本试验推翻或重写同址 atomic 串行语义。

## 何时重开

只有新的独立变量实验说明 bounded backoff 本身足以稳定控制所有原负载的启动尾部，或者明确测得更低成本、同等发布/最终确认语义的等待策略时再评估。不能只选 AIC/AIV 的中位数或开着 L4 的结果，忽略 Mix、L0 和错误退出矩阵。
