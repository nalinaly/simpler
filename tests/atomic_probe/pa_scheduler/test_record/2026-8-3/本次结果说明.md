## 测试口径

- A5 device 0，CCEC，private TensorMap；
- PA Case1，B256，共 1,280 个 task；
- 96 workers：32 AIC + 64 AIV；
- 原有 4 个 monotonic FetchMax cursor shard 保持不变；
- Selective 参与条件为
  `role_local_rank % I == (task_id % 4) % I`，`I=1/2/4/8`；
- `--enable-dep-gen --enable-l2-swimlane=4`，每档采集一次；
- 四次 execution、golden、泳道加工和排他分区校验均通过。

## I=8 下的物理 WonSlot 数量对比

在 cursor shard 仍为 4、Selective 仍为 `I=8` 的前提下，另外对比
`BlockWon` 中实际参与分配、扫描和 FinalDrain 的物理 WonSlot 数量。这里只把
活跃 WonSlot 从默认 4 改为 1 或 2；每核本地 RingSlot 仍为 4，`kWonReserve`
仍为 2。为保持 AICPU/AICore 共享内存 ABI，WonSlot=1/2 时仍为未启用槽位
保留字节空间，因此 `any_pub` 及后续字段的偏移不变。

| 物理 WonSlot | 无泳道 perf-clock Submit | 相对默认 WonSlot=4 | level-4 泳道 Submit | validation | dropped | merged 泳道 |
| ---: | ---: | ---: | ---: | --- | ---: | --- |
| 1 | 4.207473 ms | -0.292387 ms（-6.50%） | 4.512434 ms | PASS | 0 | `private_b256_shard4_selective_i8_wonslot1_4512us_merged_swimlane.json` |
| 2 | 4.882060 ms | +0.382200 ms（+8.49%） | 4.522065 ms | PASS | 0 | `private_b256_shard4_selective_i8_wonslot2_4522us_merged_swimlane.json` |
| 4（默认） | 4.499860 ms | 基线 | 4.611924 ms | PASS | 0 | `private_b256_shard4_selective_i8_4612us_merged_swimlane.json` |

本轮每个新配置只采集一次；正确性、96 核拓扑和每核 1,280 次 Submit 均通过
校验。单次结果显示 WonSlot=1 最快、WonSlot=2 反而最慢，但还不能把该排序
外推为稳定统计结论。尤其是 WonSlot=1/2 的 level-4 泳道时间只相差
9.631 us，而无泳道 perf-clock 相差 674.587 us，说明 level-4 打点已经改变
真实竞争时序，不能用泳道绝对时长替代性能测量。

## 性能口径边界

上述 Submit 是开启 level-4 泳道和 atomic/DCCI 记录后的观测值，只用于
分析执行结构和 winner/loser 时序，不能替代关闭泳道图的性能结果。

同一代码的无泳道 `perf-clock` 结果为：I=1 `4.48221 ms`、I=2
`8.19788 ms`、I=4 `7.73645/8.40528 ms`、I=8 `4.49986 ms`。I=2/I=4
的泳道绝对时间与无泳道性能方向相反；不得根据本目录四张泳道的 Submit
大小宣称 Selective 有性能收益。

该反向差异不是 selector 未生效或离线边界算错：I=2 泳道 ELF 明确带有
`PTO_FDWIC_PRIVATE_CLAIM_PARTICIPATION_INTERVAL=2`，raw 中恰好有
36,864 条 `ClaimMax` 和 1,280 个 winner，Submit 起止边界也与 perf-clock
一致。但两种 ELF 的真实累计逐核 Submit 工作量分别为 398,078,749 和
698,506,345 cycles，说明运行过程本身已经发生显著变化。当前只能把代码
布局 / Scalar I-cache 与打点改变竞争到达、winner 分布列为待验证候选，
不能在缺少同 ELF 受控 A/B 或 PMU 证据时指定单一原因。
