# CSA Scalar热循环：记录特化与冷错误写出

日期：2026-10-29。目标仍为完整Device中位数低于1500us，本项不单独代表达标。

## 问题与边界

最新L1还有508.134us全核计算空窗。除了具体GM访问，Scalar完成、准入、发布等路径的
编译形态也值得核验。原有`run_resident_scheduler<WithProfiling>`已区分记录状态，
但其下的`run_ready_dispatch_loop`是两种入口共用的独立函数，profiling等级仍为动态参数。
ELF符号表显示AIC／AIV的该函数分别为302656／303560B。
这只能证明代码尺寸，不能据此宣称已测得指令缓存缺失或某段空窗的具体来源。

本项仅让调度循环复用已有WithProfiling模板参数，无记录版本以编译期常量0处理等级。
已有入口选择不变：L1及以上，或者启用sampled task timing，仍走有profiling状态的版本。
没有新环境变量、用户开关、协议字段或额外运行时查询；错误门禁、三lane义务、
Ready／准入／完成逻辑、54个业务kernel、2308个执行身份及完整Device计时范围不变。

新无记录循环的AIC／AIV尺寸为278960／284868B，分别减少约7.83%／6.16%；
有记录循环的尺寸保持不变。只看尺寸不作保留决定，下面另做性能及正确性验证。
进一步强制内联到无记录入口的拓展没有获得预期体积收益，已单独撤回，见
[编译实验记录](../../../../docs/zh-cn/investigations/2026-10-csa-inline-hotloop.md)。

普通多block、sync_start、GM Mix三个scene class的全部匹配用例在A5及A5sim通过。
严格CSA L4通过2308执行身份、133依赖及46733协议事件审计，七项golden通过。
有记录版本仍保持原记录路径，不能把其泳道区间变化直接归因于无记录版本特化。
本次没有用新的源码字符串断言冒充行为TDD，也没有改变原边界断言以迁就候选。

A5完整HBG范围88通过、4跳过、4取消选择，保留Host／设备日志，CLI竞争观察为空。
首次A5sim整批为66通过、1失败、29取消选择；失败为GM Mix独立任务没有时间重叠，
执行计数、身份、依赖及输出检查均已通过。该类单独复跑通过，原失败记录不删除。
原用例只用有限延时扩大重叠机会，没有互等peer进入的强制见证；该失败不能单独证明
生产实现新增了全任务完成屏障。停止其他回归后，同源码／二进制、原顺序完整仿真复跑
67通过、29取消选择；这不等于已证明首次失败的具体时序原因。未放宽原断言，

增加peer entry／等待分支／超时检查；该测试修复不计入本项性能收益。
本项保留编译特化。首次失败、隔离通过及整批复跑日志均保留于工作区outputs。
随后完整C++构建还发现两个直接调用executor的测试遗漏模板参数；这属于测试迁移遗漏。

覆盖level0但启用采样及profiling指针真正为空，保留原身份、代次和协议顺序断言。
上述特化单项验收当时未含完整故障矩阵，下文检查点已补做；最终1500us验收仍未完成。

## 冷错误写出独立成函数

`scheduler_record_error`的基础写出函数改为本翻译单元内的noinline函数，函数体不变。
热路径仍逐次执行原`read_error`；首错CAS、完整身份、cache barrier和最后状态发布均保留。
ELF中AIC／AIV各有一份LOCAL绑定的592B写出函数，没有新增跨核共享的弱符号实现。
无记录循环从278960／284868B降至203436／206944B，约减少27.1%／27.4%。
没有改变shared state、ABI或v5协议；代码尺寸下降不是指令缓存缺失的直接测量。
